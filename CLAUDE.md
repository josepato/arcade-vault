## Project

Arcade Vault — a platform for playing games online and competing for the highest score/points (per README.md). The codebase is currently the unmodified output of `create-next-app`: no game logic, routes, or data layer exist yet beyond the default landing page.

## Commands

- `npm run dev` — start the dev server
- `npm run build` — production build (fails on TypeScript errors, since `typescript.ignoreBuildErrors` is not set in `next.config.ts`)
- `npm run start` — run the production build
- `npm run lint` — ESLint via the flat config in `eslint.config.mjs` (`eslint-config-next` core-web-vitals + typescript rules)

No test runner is configured yet.

## Architecture

- Next.js App Router (`app/` directory), TypeScript (strict), Tailwind CSS v4.
- Tailwind v4 has no `tailwind.config`; theme tokens (colors, fonts) are defined in `app/globals.css` via `@theme inline`, driven by CSS custom properties (`--background`/`--foreground`) that swap under `prefers-color-scheme: dark`.
- `app/layout.tsx` — root layout; loads Geist Sans/Mono via `next/font/google` and sets global `metadata`.
- `app/page.tsx` — the only route so far, the default create-next-app landing page.
- Path alias `@/*` maps to the repo root (`tsconfig.json`).

## Next.js 16 in this repo (breaking changes vs. older training data)

Per `AGENTS.md`, read the vendored docs at `node_modules/next/dist/docs/01-app/` before using an App Router API — behavior may not match what you already know. Notable differences already in play here:

- Route-aware type helpers `PageProps<'/route'>` and `LayoutProps<'/route'>` are generated globally (no import needed) by `next dev`/`next build`/`next typegen`. `app/layout.tsx` already uses `LayoutProps<"/">` — use these helpers for new pages/layouts instead of hand-written prop types.
- `params` and `searchParams` are `Promise`s in Server Components/pages and must be `await`ed.
- `next-env.d.ts` is regenerated by the `next` CLI — never hand-edit it.
